================================================================================
PicoGK AUTOMATED CFD EVOLUTION FRAMEWORK - SERVER OPERATIONS MANUAL (CONSOLIDATED)
================================================================================
Dieses Dokument ist das zusammengeführte und aktualisierte Handbuch, um das 
Framework auf einem Linux-Hochschulserver (Ubuntu, ohne Sudo/Admin-Rechte) von 
Grund auf einzurichten, zu betreiben, zu überwachen und zu debuggen.

Es führt die Inhalte aus den bisherigen Einrichtungsdateien zusammen, bereinigt
veraltete Pfade/Befehle und stellt sowohl den vollautomatischen Weg über Skripte
als auch den lückenlosen manuellen Weg für Einzelschritte bereit.

================================================================================
ÜBERSICHT: DIE ZWEI WEGE
================================================================================
1. DER AUTOMATISIERTE WEG (EMPFOHLEN):
   - Initiales Server-Setup: 'setup_server.sh' (unter 'src/Automatisierung_v2/setup_server.sh')
     installiert und kompiliert alle Abhängigkeiten vollautomatisch in einem Rutsch.
   - Steuerung im Alltag: Die Skripte unter 'scripts/' ('sim.ps1' für Windows, 
     'sim-runner.sh' für Linux) übernehmen Deployment, Build, tmux-Handling,
     xvfb-run, Live-Monitoring, Statusprüfungen und den Ergebnis-Download komplett
     automatisch. Kein manueller SSH-Handgriff ist im Regelbetrieb nötig!

2. DER MANUELLE WEG (SCHRITT-FÜR-SCHRITT):
   - Wenn ein Schritt hakt, Anpassungen nötig sind oder kein Bash-Skript genutzt
     werden kann, enthält Teil 2 dieses Dokuments alle Einzelschritte von Hand.

1.1 INITIALES SERVER-SETUP VIA 'setup_server.sh'
------------------------------------------------
Wenn du auf einen neuen Server umziehst oder die Umgebung zurücksetzen willst:

1. Kopiere das Skript 'src/Automatisierung_v2/setup_server.sh' auf den Server.
2. Skript ausführbar machen und ausführen:
   chmod +x setup_server.sh
   ./setup_server.sh

Hinweis zu Anaconda Terms of Service:
Fragt Conda nach der Zustimmung zu den Nutzungsbedingungen, führe folgendes aus:
   export PATH=$HOME/miniconda/bin:$HOME/.dotnet:$HOME/software/bin:$HOME/software/gmsh-4.11.1-Linux64/bin:$PATH
   export LD_LIBRARY_PATH=$HOME/miniconda/lib:$LD_LIBRARY_PATH
   conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/main
   conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/r
Danach ggf. 'conda self update' und das Skript erneut starten.

WICHTIG NACH DEM SETUP:
Einmal aus der SSH-Sitzung ausloggen und neu einloggen, damit alle Umgebungsvariablen
in '~/.bashrc' aktiv werden!


1.2 ALLTAGSBETRIEB ÜBER DIE 'scripts/'-WERKZEUGE
------------------------------------------------
Sobald das Erst-Setup einmalig durchgelaufen ist, müssen im Alltag keine manuellen
Befehle mehr auf dem Server eingetippt werden.

Von Windows aus (PowerShell):
   .\scripts\sim.ps1 doctor                # Prüft SU2, MPI, Gmsh, dotnet, libpicogk auf dem Server
   .\scripts\sim.ps1 run -Project MantaAuv # Lädt Code hoch, baut, startet tmux + xvfb-run
   .\scripts\sim.ps1 status                # Zeigt Laufstatus, Laufzeit und Zahl der Generationen
   .\scripts\sim.ps1 log                   # Live-Stream des Simulationslogs (Strg+C beendet Anzeige)
   .\scripts\sim.ps1 fetch                 # Lädt fertige CSV + Logs nach .\Serverergebnisse\
   .\scripts\sim.ps1 stop                  # Beendet Lauf und alle Unterprozesse sauber

Direkt auf dem Linux-Server (falls ohnehin eingeloggt):
   cd ~/Documents/AutomatisierungCleanVersion
   bash scripts/sim-runner.sh doctor
   SIM_PROJECT=MantaAuv bash scripts/sim-runner.sh run
   bash scripts/sim-runner.sh status
   bash scripts/sim-runner.sh log
   bash scripts/sim-runner.sh stop

2.5 PICOGK RUNTIME KOMPILIEREN (Headless-Modus)
----------------------------------------------
cd ~/software
git clone --recursive https://github.com/leap71/PicoGKRuntime.git ~/software/PicoGK

# C++ Typ-Fix in PicoGKTrace.h (oMS ist duration, count() liefert den Skalar):
sed -i 's/std::cerr << oMS << " elapsed\\n";/std::cerr << oMS.count() << " elapsed\\n";/g' ~/software/PicoGK/Source/PicoGKTrace.h

# Compiler-Flags für Conda-Pfade setzen:
export PKG_CONFIG_PATH=$HOME/miniconda/lib/pkgconfig:$PKG_CONFIG_PATH
export CFLAGS="-I$HOME/miniconda/include"
export CXXFLAGS="-I$HOME/miniconda/include"
export LDFLAGS="-L$HOME/miniconda/lib"

# Build-Ordner vorbereiten und konfigurieren:
rm -rf ~/software/PicoGK/build/* || true
mkdir -p ~/software/PicoGK/build && cd ~/software/PicoGK/build

# WICHTIG: -DGLFW_BUILD_X11=ON ist Pflicht, damit xvfb-run das virtuelle Display anbinden kann!
~/software/cmake-3.29.3-linux-x86_64/bin/cmake \
  -DCMAKE_PREFIX_PATH=$HOME/miniconda \
  -DBoost_ROOT=$HOME/miniconda \
  -DBoost_NO_SYSTEM_PATHS=ON \
  -DPICOGK_NO_VIEWER=ON \
  -DGLFW_BUILD_WAYLAND=OFF \
  -DGLFW_BUILD_X11=ON \
  -DCMAKE_POLICY_DEFAULT_CMP0144=NEW \
  -DPKG_CONFIG_EXECUTABLE=$HOME/miniconda/bin/pkg-config ..

make -j $(nproc)

# Bibliothek in den .NET-Ausgabeordner kopieren (unter beiden Namen!):
TARGET_BIN="$HOME/Documents/AutomatisierungCleanVersion/src/Automatisierung_v2/bin/Debug/net9.0"
mkdir -p "$TARGET_BIN"
PICOGK_LIB=$(find ~/software/PicoGK/build -iname "*picogk.so" | head -n 1)
cp "$PICOGK_LIB" "$TARGET_BIN/libpicogk.so"
cp "$PICOGK_LIB" "$TARGET_BIN/libpicogk.26.2.so"

3.3 SIMULATION STARTEN (BACKGROUND RUN MIT TMUX)
------------------------------------------------
Da SSH-Sitzungen bei Netzwerkunterbrechung beendet werden, läuft die Simulation
immer innerhalb eines virtuellen tmux-Terminals:

Schritt 1: Alte, hängende Prozesse gezielt aufräumen:
pkill -9 -f Automatisierung_v2.dll || true
pkill -9 -f SU2_CFD || true
pkill -9 -f mpirun || true
pkill -9 -f Xvfb || true

Schritt 2: Neue Tmux-Sitzung öffnen:
~/miniconda/bin/tmux new -s sim

Schritt 3: Simulation innerhalb des Tmux-Fensters starten:
cd ~/Documents/AutomatisierungCleanVersion
export PATH=$HOME/miniconda/bin:$HOME/.dotnet:$HOME/software/bin:$HOME/software/gmsh-4.11.1-Linux64/bin:$PATH
export LD_LIBRARY_PATH=$HOME/miniconda/lib:${LD_LIBRARY_PATH:-}
export HWLOC_HIDE_ERRORS=1
export LIBGL_ALWAYS_SOFTWARE=1

# Startet das gewünschte Projekt (z. B. MantaAuv) headless mit virtuellem X-Server:
xvfb-run -a dotnet run --project src/Automatisierung_v2 -- MantaAuv > simulation.log 2>&1

Schritt 4: Sicher abkoppeln (Detach):
Drücke auf der Tastatur:
1. STRG + B (gleichzeitig drücken, loslassen)
2. Taste D (Detach)
Der grüne tmux-Balken verschwindet. Du bist wieder im normalen Terminal und kannst
die SSH-Verbindung schließen. Das Framework rechnet auf dem Server weiter.


3.4 SIMULATION ÜBERWACHEN (MONITORING)
-------------------------------------

   ~/miniconda/bin/tmux attach -t sim

4.2 CHECKLISTE BEI FEHLERN
--------------------------

- FEHLER: "symbol lookup error" bei mpirun / OpenMPI
  Ursache: Das System verwendet ein unpassendes globales OpenMPI anstelle der
  Conda-Version.
  Lösung: 'which mpirun' prüfen. Es MUSS '$HOME/miniconda/bin/mpirun' sein.
  Sicherstellen, dass '$HOME/miniconda/bin' im PATH ganz vorne steht.

- FEHLER: "prterun was unable to launch" / "Executable not found"
  Ursache: SU2_CFD liegt nicht unter dem in der Konfiguration angegebenen Pfad.
  Lösung: Prüfe mit 'ls -l ~/software/bin/SU2_CFD', ob die Datei existiert und
  ausführbar ist ('chmod +x ~/software/bin/SU2_CFD').

- FEHLER: "DllNotFoundException: Unable to load shared library 'libpicogk'"
  Ursache: Die C++ PicoGK-Bibliothek fehlt im bin-Verzeichnis der Anwendung.
  Lösung:
  cp $(find ~/software/PicoGK/build -iname "*picogk.so" | head -n 1) \
     ~/Documents/AutomatisierungCleanVersion/src/Automatisierung_v2/bin/Debug/net9.0/libpicogk.so
  cp $(find ~/software/PicoGK/build -iname "*picogk.so" | head -n 1) \
     ~/Documents/AutomatisierungCleanVersion/src/Automatisierung_v2/bin/Debug/net9.0/libpicogk.26.2.so

- CPU-AUSLASTUNG NUR 100% (Single-Core statt Multi-Core):
  Ursache: SU2 läuft nicht über mpirun oder 'MpiCores' ist auf 1 gesetzt.
  Lösung: Prüfe in 'src/projects/<Projekt>/simulation.json', ob 'MpiCores' auf
  mehrere Kerne konfiguriert ist und 'MpiRunPath' auf das Conda-mpirun zeigt.
  Prüfe mit 'top -u $USER', ob mehrere 'SU2_CFD'-Prozesse aktiv sind.

- FEHLER: "X connection broken" / "Display already in use"
  Ursache: Ein alter Xvfb-Prozess belegt das Display.
  Lösung: Verwende immer das Flag '-a' bei xvfb-run ('xvfb-run -a ...') und
  beende hängende Instanzen mit 'pkill -9 -f Xvfb'.

- HINWEIS ZU KONFIGURATIONEN:
  Pfade und Kerne werden NICHT mehr im C#-Code geändert, sondern zentral in
  'src/projects/<Projektname>/simulation.json' oder für temporäre lokale
  Abweichungen in 'config/simulation.local.json' hinterlegt.
